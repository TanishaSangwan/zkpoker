# Real, deployed, on-chain shuffle-proof verifier

Generated by Garaga from a real Barretenberg verification key for
`circuits/shuffle/src/main.nr` (the V2 shuffle circuit, see
`docs/V2-MENTAL-POKER.md`). This is not a mock — declared and deployed to a
local `starknet-devnet`, it genuinely accepted a real shuffle proof and
genuinely rejected a corrupted one. See `docs/V2-SPIKE-RESULTS.md` §7–§8 for
the full writeup and measured gas cost.

**Deployed contract exposes:**
```
fn verify_ultra_keccak_zk_honk_proof(
    self: @TContractState, full_proof_with_hints: Span<felt252>,
) -> Result<Span<u256>, felt252>
```
`Ok(public_inputs)` on a valid proof (the 4 values: `pk_x, pk_y, hash_in,
hash_out`), `Err(reason)` on an invalid one. **This is not the same
interface PokerGame's `IShuffleVerifier::verify_shuffle` expects** — wiring
this in for real needs a thin adapter contract translating between the two,
not a direct swap for `MockShuffleVerifier`. Not built yet.

## The toolchain gotcha this whole thing hinges on

`garaga gen`'s Honk VK parser hardcodes `public_inputs_offset == 1`. The
project's normal pinned toolchain (`nargo 1.0.0-beta.22` + `bb
5.0.0-nightly.20260522`, chosen for the spike's gate-count measurements)
produces VKs with `offset = 5` — Garaga rejects them outright, reproduced
identically across two different modern `bb.js` releases. **This is a real,
diagnosed incompatibility, not a flag to tweak away.**

The fix: Garaga's own docs pin a specific, older pairing —
**`nargo 1.0.0-beta.16` + `@aztec/bb.js@3.0.0-nightly.20251104`** — and a
VK generated with *that* pairing has `offset = 1`. Confirmed by generating
this verifier successfully, then having `garaga gen` itself print:
"Detected versions of bb and nargo are not compatible with the required
versions by garaga 1.1.0" when run against anything newer.

**Circuit-side changes needed to compile under beta.16** (see
`example_proof/beta16_build/` for the exact patched source used):
- `EmbeddedCurvePoint::new(x, y)` doesn't exist in beta.16's stdlib —
  it's a plain struct literal there: `EmbeddedCurvePoint { x, y,
  is_infinite: false }`.
- The pinned `poseidon` crate (`v0.3.0`, chosen in `circuits/shuffle/`'s own
  `Nargo.toml` for compatibility with the *newer* Noir) doesn't compile
  under beta.16 — its `poseidon2_permutation` calls a stdlib function whose
  signature changed. `v0.1.1` (the version current at beta.16's release
  era) works.
- Non-ASCII characters in comments (`──`, `—`, `·`) aren't accepted by
  beta.16's parser — ASCII-only in the beta.16 copy.

None of this touches the real, pinned `circuits/shuffle/` — that stays on
the newer toolchain for its own gate-count/proving-time numbers.
`example_proof/beta16_build/` is a separate, parallel copy that exists only
to feed Garaga.

## Reproducing this

```bash
# 1. Get the matched toolchain (separate from the project's normal pin)
noirup --version 1.0.0-beta.16
npm install @aztec/bb.js@3.0.0-nightly.20251104   # in a scratch dir

# 2. Compile the beta16-patched circuit copy, execute against the real
#    Prover.toml already checked in at circuits/shuffle/Prover.toml
cd example_proof/beta16_build && nargo execute

# 3. Prove + get the VK (Node script using @aztec/bb.js's UltraHonkBackend,
#    generateProof/getVerificationKey with { keccakZK: true })

# 4. Generate the verifier contract
garaga gen --system ultra_keccak_zk_honk --vk vk.bin --project-name shuffle_verifier

# 5. Generate real calldata for a specific proof (needs a *raw binary*
#    public-inputs file — 32 bytes big-endian per field, NOT the JSON array
#    bb.js's generateProof() returns; convert it first)
garaga calldata --system ultra_keccak_zk_honk --proof proof.bin --vk vk.bin \
  --public-inputs public_inputs.bin --format array
```

`scarb 2.16.1` and `starknet-foundry 0.57.0` are what Garaga's generator
pins (see `.tool-versions` in this directory) — also different from the
main project's `cairo/.tool-versions` (2.18.0). Both installed via `asdf`
alongside the existing versions; nothing in `cairo/` was touched.
